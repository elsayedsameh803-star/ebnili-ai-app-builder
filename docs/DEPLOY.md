# دليل النشر — إبنيلي

> كل الأوامر هنا **تُنسخ وتُنفَّذ على جهازك أنت**. الموقع لا ينفّذ أي أمر
> نيابة عنك ولا يلمس ملفاتك — وهذا قرار أمني مقصود (انظر «لماذا لا طرفية حقيقية»).

## أولاً: التشغيل المحلي

```bash
npm install
npm run dev
```

الموقع يفتح على `http://localhost:3000`.

## ثانياً: البناء

```bash
npm run build     # ينتج الموقع في مجلد dist/
npm run preview   # معاينة نسخة الإنتاج محلياً
```

## ثالثاً: النشر

اختر طريقة واحدة:

### الطريقة A — Vercel (الأسهل)

```bash
npx vercel --prod
```

سيسألك تسجيل الدخول مرة واحدة عبر المتصفح، ثم ينشر الموقع مباشرة.

### الطريقة B — Netlify

```bash
npx netlify deploy --prod --dir=dist
```

### الطريقة C — GitHub (الأفضل للتحديثات المستمرة)

أنشئ مستودعاً فارغاً على GitHub، ثم:

```bash
git init
git add .
git commit -m "Initial commit"
git remote add origin https://github.com/<حسابك>/<مستودعك>.git
git branch -M main
git push -u origin main
```

اربط المستودع في Vercel أو Netlify. بعد هذه الخطوة، كل نشر جديد =
`git push` فقط.

## رابعاً: الأسرار

انسخ `.env.example` إلى `.env` وضع قيمك فيه. الملف `.env` مُدرج في
`.gitignore` — لا ترفع مفاتيح حقيقية إلى GitHub أبداً.

---

## لماذا لا توجد طرفية حقيقية داخل الموقع؟

المشاريع يُنشئها الذكاء الاصطناعي من ملاحظات المستخدم. تشغيل أوامر
(`child_process.exec`) على سيرفر Vercel **ليس صندوق حماية**:

- كل `process.env` في السيرفر يصبح متاحاً (رابط قاعدة البيانات، توكن S3، مفاتيح AI)
- اسم ملف واحد مصمَّم بالذكاء الاصطناعي يكفي لتنفيذ كود عن بُعد

لذلك حدّدنا الحدّ في المنتج: الموقع **ينتج نصاً** فقط، وأنت من يشغّله في
طرفيتك. هذا يحمي الخادم، ويحمي مفاتيحك، ويمنع أي مشروع من الخروج عن السيطرة.

## التحقق من مفاتيحك

الموقع يعرض حالة الإعداد على `/api/health`:

- `status: "ok"` = كل شيء مُعد بشكل صحيح
- `status: "degraded"` = راجع قائمة `problems` لمعرفة الناقص

## بعد النشر

- المتطلب الوحيد: Node.js 18 أو أحدث
- الأسرار عبر متغيرات البيئة في لوحة الاستضافة، وليس في الكود
